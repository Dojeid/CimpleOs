Falkon-OS — A 64-bit Educational Hobby Operating System

Falkon-OS is a monolithic, freestanding kernel written in C, a small amount of C++, and NASM assembly. It boots from a custom El-Torito ISO via a two-stage bootloader, enters 64-bit Long Mode with 4-level paging, and provides a Windows 11–style framebuffer desktop, POSIX-like syscalls, a Linux-inspired shell, and 16 built-in GUI applications.

Build & Run Architecture

Key Features

  • Custom boot chain: BIOS bootsector → Multiboot stub → Long Mode → kmain()
  • Memory: PMM bitmap allocator, 4-level VMM, kernel heap (kmalloc), slab cache
  • Filesystem: VFS with EXT4, FAT32, and in-memory ramdisk at boot
  • Networking: Intel e1000 NIC driver, IP/TCP/DNS stack for the Browser app
  • Processes: Up to 16 processes, round-robin scheduler, 55+ syscalls
  • Desktop GUI: Window manager, taskbar, start menu, 16 apps, double-buffered rendering
  • Shell: 50+ commands including built-in C compiler (gcc/tcc)
  • Runlevels: Runlevel 5 (GUI desktop) and Runlevel 3 (TTY console)

Quick Start

git clone https://github.com/Saravanan-Codez/Falkon-Os.git
cd Falkon-Os
python build.py -check          # verify toolchain
python build.py -build          # compile kernel + ISO
python build.py -run            # launch in QEMU

Output ISO: out/FalkonOS.iso

🪟 Windows Setup

Build Falkon-OS natively on Windows using Python, CMake, NASM, and a freestanding ELF toolchain.

Required Tools

  • Python 3.8+ — python.org (check "Add to PATH")
  • CMake 3.16+ — winget install Kitware.CMake
  • NASM — winget install NASM.NASM
  • Clang + LLD — Windows builds use clang targeting x86_64-elf with ld.lld (MinGW cannot produce proper ELF kernels)
  • QEMU — winget install QEMU.QEMU (primary run target via build.py -run)
  • VirtualBox (optional) — for manual ISO boot; see Running the OS

Build Steps

  1. Clone and enter the repository: 
    git clone https://github.com/Saravanan-Codez/Falkon-Os.git
cd Falkon-Os
  2. Verify your environment: 
    python build.py -check
  3. Build and run: 
    python build.py -build
python build.py -run
Tip: Run python build.py -check first. It detects missing tools and suggests install commands for your OS. Custom tool paths are saved to falkon.ini.

python3 build.py -run kvm        # use KVM acceleration on Linux

⚙️ WSL2 Setup

Compile inside WSL2, then run the ISO in QEMU on Windows or attach it to VirtualBox.

  1. Install WSL2: wsl --install -d Ubuntu
  2. Install build tools inside WSL: 
    sudo apt update && sudo apt install -y python3 build-essential cmake ninja-build nasm
  3. Navigate to the project (adjust drive letter as needed): 
    cd /mnt/d/Falkon_labs/Falkon-Os
  4. Build the ISO: 
    python3 build.py -build
  5. Run from Windows PowerShell (QEMU installed on Windows): 
    python build.py -run

🐍 build.py — Cross-Platform Build Driver

The single entry point for compiling, testing, and running Falkon-OS. Located at the repository root.

Build Pipeline

1. CMake configure + compile (src/**/*.c, *.asm)
⬇️
2. NASM assemble bootsector → build/bootsector.bin
⬇️
3. objcopy → build/FalkonOS_flat.bin (raw kernel binary)
⬇️
4. tools/iso_builder.c → El-Torito ISO 9660 image
⬇️
5. Output → out/FalkonOS.iso + out/build_report.json

▶️ Running the OS

QEMU (Recommended — automated via build.py)

python build.py -run
python build.py -run kvm      # hardware acceleration
python build.py -run debug    # GDB stub :1234

QEMU settings are read from falkon.ini (512 MB RAM, q35 machine, std VGA).

VirtualBox (Manual setup)

build.py does not auto-create VirtualBox VMs. Attach out/FalkonOS.iso manually:

  1. New VM: Linux → Other Linux (64-bit)
  2. RAM: 512 MB, no hard disk
  3. Display: VMSVGA, 16 MB VRAM
  4. Pointing device: PS/2 Mouse
  5. Storage: attach FalkonOS.iso to optical drive

🧠 System Architecture

Falkon-OS uses a monolithic kernel design — all kernel code, drivers, GUI, and shell are linked into one ELF binary.

Subsystem Map

📁 src/arch/x86_64/ — Boot assembly, linker script, ISR/IRQ stubs
📁 src/kernel/ — GDT, IDT, timer, processes, syscalls, shell, ACPI
📁 src/mm/ — PMM, VMM, heap, slab allocator
📁 src/drivers/ — Video, input, storage, network, audio, PCI, USB
📁 src/fs/ — VFS, EXT4, FAT32, ramdisk
📁 src/net/ — IP, TCP, DNS
📁 src/gui/ — Desktop, window manager, taskbar, 16 apps
📁 src/lib/ — Freestanding printf, string, I/O, FFmpeg stubs
📁 tools/ — ISO builder (iso_builder.c)

Kernel Initialization Order (kmain in src/kernel/main.c)

  1. GDT install
  2. PMM init (physical frame allocator)
  3. VMM init (4-level paging)
  4. Heap + slab allocator
  5. Graphics init (VBE/Bochs framebuffer, double buffering)
  6. IDT + PIC remap
  7. CPUID, PS/2 mouse, PIT timer (100 Hz)
  8. USB, sound, ATA, RTC, ACPI, clipboard, PTY
  9. e1000 NIC + IP stack init
  10. Desktop, taskbar, cursor, notifications
  11. VFS + EXT4 mount attempt + ramdisk seed
  12. Process scheduler + syscall dispatcher
  13. Terminal, window manager → main GUI loop (Runlevel 5)

🚀 Boot Process

Two-stage boot: custom BIOS bootsector, then Multiboot-compatible Long Mode transition. No GRUB required.

Stage 1 — bootsector.asm (src/arch/x86_64/boot/bootsector.asm)

  • Loaded by BIOS at 0x7C00 (512-byte MBR boot sector)
  • Reads kernel from disk via INT 13h (512-byte sectors or 2048-byte ISO sectors)
  • Validates ELF (0x7F ELF) or Multiboot (0x1BADB002) magic
  • Enables A20 line, sets VBE 1024×768×32 mode
  • Enters 32-bit protected mode, jumps to kernel at 0x00100010

Stage 2 — boot.asm (src/arch/x86_64/boot/boot.asm)

  • Multiboot 1 header at link address 1 MB (linker.ld)
  • CPUID check + Long Mode availability test
  • Builds 4-level page tables (identity map 4 GB via 2 MB pages)
  • Enables PAE, sets EFER.LME, enables paging
  • Far jump to 64-bit code segment → calls kmain()
Note: On the primary bootsector path, Multiboot info (ebx) is passed as 0, so kmain may receive mbi = NULL. Graphics uses VBE mode set by the bootsector; PMM defaults to 128 MB if no memory map is available.

💾 Memory Management

PMM — Physical Memory Manager

src/mm/pmm.c

  • Bitmap-based 4 KB frame allocator
  • Initialized from Multiboot memory map or 128 MB fallback
  • API: pmm_alloc_frame(), pmm_free_frame()

VMM — Virtual Memory Manager

src/mm/vmm.c

  • 4-level paging (PML4 → PDPT → PD → PT)
  • Extends boot-time identity map from boot.asm
  • Supports map/unmap, NX bit, page cloning for fork

Kernel Heap

src/mm/heap.c

  • kmalloc() / kfree() for dynamic kernel allocations

Slab Allocator

src/mm/slab.c

  • Object cache for fixed-size kernel structures

⚡ Interrupts & System Calls

GDT / IDT / PIC

  • src/kernel/gdt.c — 64-bit GDT + TSS
  • src/kernel/idt.c — 256-entry IDT, PIC remapped to vectors 32–47
  • src/arch/x86_64/kernel/interrupts.asm — ISR stubs (0–31), IRQ stubs, syscall80 gate
  • src/kernel/timer.c — PIT at 100 Hz (IRQ0), drives timer_wait() and uptime

Syscall Interface

src/kernel/syscall.c — 55+ POSIX-like syscalls defined in syscall.h:

SYS_READ=1   SYS_WRITE=2   SYS_OPEN=3
SYS_MALLOC=4 SYS_FORK=13   SYS_MMAP=12
SYS_SOCKET=20 SYS_PIPE=25  SYS_PTHREAD_CREATE=41
SYS_SHM_OPEN=48 ... SYS_GETGID=55

Process Model

src/kernel/process.c — Up to 16 processes, round-robin scheduler, states: READY, RUNNING, BLOCKED, TERMINATED. Supports fork, waitpid, kill, ELF program loading.

📁 Filesystem (VFS)

Linux-style virtual filesystem with superblock, inode, dentry, and file operations.

VFS Core — src/fs/vfs.c

  • Mount API: vfs_mount(dev, path, fstype)
  • File ops: open, read, write, close, mkdir, unlink
  • Path resolution via dentry cache

EXT4 — src/fs/ext4.c

Read support: superblock parsing, inode tables, block groups. Mounted at / on /dev/hda if available.

FAT32 — src/fs/fat32.c

FAT32 driver registered with the VFS mount layer.

Ramdisk — src/fs/ramdisk.c

Seeds demo content at boot:

  • /docs/welcome.txt — welcome message
  • /sys/config.ini — kernel config
  • /bin/ — demo ELF binaries (vlc, notepad, calc)
  • /videos/sample.mp4 — media sample

🌐 Network Stack

Intel e1000 NIC — src/drivers/net/e1000.c

  • Probes PCI bus for Intel 82540EM (vendor 0x8086, device 0x100E)
  • QEMU's default virtual NIC; also works in VirtualBox with Intel PRO/1000
  • MAC: 52:54:00:12:34:56

Protocol Stack

  • src/net/ip.c — IPv4, ARP cache, default IP 10.0.2.15 (QEMU slirp)
  • src/net/tcp.c — TCP sockets (connect, send, recv)
  • src/net/dns.c — DNS resolution

🔧 Troubleshooting

IssueCauseSolution
clang: command not found (Windows) Missing ELF-capable compiler Install LLVM/Clang with LLD linker; run python build.py -check
nasm: command not found NASM not in PATH winget install NASM.NASM or sudo apt install nasm
QEMU not found QEMU not installed or not in PATH Install QEMU; set path in falkon.ini [paths]
Black screen in VirtualBox Wrong graphics controller Set Graphics Controller to VMSVGA, VRAM to 16 MB
Mouse not moving in VM USB tablet overriding PS/2 Set Pointing Device to PS/2 Mouse in VM settings
Build fails on Windows with MinGW GCC MinGW cannot produce freestanding ELF Use Clang + LLD (clang, ld.lld) as configured in CMakeLists.txt
CMake configure error Missing CMake or Ninja Install CMake 3.16+; Ninja is optional but preferred
